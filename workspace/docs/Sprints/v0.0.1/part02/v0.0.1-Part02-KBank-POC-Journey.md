## 用户需求（一句话）

> **【需求 #REQ-2026-001】** 客户身份证件过期后，系统必须拦截该客户新发起的资金交易（转账 / 开户 / 贷款申请），直至证件信息更新。

## 第一部分 · 当前状态（POC 启动时）

### 1.1 系统已具备的能力（Fineract 原生，零开发即存在）

| 能力 | 现状 |
|---|---|
| 客户与证件数据 | `m_client_identifier` 已含 `expiry_date` / `issuance_date`（**数据在，但没人用它做拦截**） |
| 储蓄 / 贷款 / 交易 API | 603 端点全可用，转账、开户、贷款申请、放款、还款均可正常执行 |
| 渠道雏形 | 手机银行（Flutter，简化登录）+ Backoffice（React）——设计稿时原表述「已有基础页面骨架」与实际不符（2026-11-06 实测 `channels/` 下仅 `website/`，全仓无 `.dart`）；2026-11-07 P1.3/P1.4 落地后成立（全页面可操作原型），P3 接线后为生产可用渠道（Part02 挂账修正回写） |

### 1.2 缺失的能力：证照过期拦截（本次 POC 要补的核心）

**当前没有任何代码把「证件有效期」与「交易」关联起来。** 具体表现为：

- 客户证件已过期 → 依然能**正常转账、开户、申请贷款**，无任何提示或阻止；
- 手机银行首页**没有**「证件过期」告警横幅，提交交易**没有**拦截弹窗；
- Backoffice 客户详情**没有**「证件过期」状态标红，也**没有**证件编辑修复入口；
- 网关只做路由转发，**没有**交易拦截过滤器。

### 1.3 当前状态的直观证据（POC 现场可演示的「缺口」）

> 演示动作：让证件已过期的客户 A 登录手机银行 → 发起转账 → **转账成功入账**。
> 观众一眼看到：监管要求没有被满足——这正是需求尚未实现的起点状态。

## 第二部分 · 目标状态（POC 结束时）

### 2.0 从当前到目标：ASDM 开发流程（POC 的主演示线）

在 POC 过程中，通过 ASDM 开发流程把上面的「缺口」补上：

```
需求受理(alink 数字员工认领)
  → 影响分析(KE 知识图谱 A/B 对比：改动面 = 客户/储蓄/贷款/网关)
  → 方案设计(定案：网关拦截过滤器 + 渠道交互)
  → 编码执行(alink 运行时协同，产出代码)
  → 测试回归(12 步冒烟 + 200 官方 E2E)
  → 部署 → 目标状态达成
```

**最终产出的增量只有一个核心**：网关「写交易前校验证件是否过期」的过滤器，外加手机银行 / Backoffice 的对应交互界面。

### 2.1 目标状态用户旅程（实现后，可现场演示的闭环）

#### Step 1 · Backoffice：运营管理员定位「过期证照客户」
- **界面**：登录后台 → 客户管理 → 客户列表（证件状态列）→ 客户详情，证件有效期**标红「已过期」**
- **底层**：内部网关 `GET /clients`、`GET /clients/{id}/identifiers` → Fineract 原生端点

#### Step 2 · 手机银行：客户 A 登录
- **界面**：登录页（用户名+密码；指纹按钮/安全键盘仅作视觉占位）
- **底层**：简化登录 `POST /login`（网关做 `用户名→clientId` 映射）

#### Step 3 · 手机银行：首页出现「证件过期」红色横幅 + 账户总览
- **界面**：顶部告警横幅「证件已过期，请前往网点更新」，下方账户余额正常显示
- **底层**：网关聚合 `GET /me` + `GET /me/identity`（由 `expiry_date` 计算状态）+ `GET /me/accounts`

#### Step 4 · 手机银行：发起转账 → 被拦截 ★ 核心演示点
- **界面**：转账页填金额 → 提交 → 弹窗「证件已过期，交易已被拦截」
- **底层**：**网关拦截过滤器**（服务端权威）拦截写交易，返回 403，**不转发 Fineract**；记录一条拦截日志

#### Step 5 · 手机银行：定期开户 / 贷款申请同样被拦
- **界面**：点「定期存款」「申请贷款」→ 同样被同一过滤器拦截
- **底层**：同一规则覆盖 `POST /savings`、`POST /loans`

#### Step 6 · 手机银行：查询交易明细（只读，不拦截）
- **界面**：明细正常展示（含 runningBalance）
- **底层**：过滤器只拦写、不拦读

#### Step 7 · Backoffice：更新证件有效期（修复）
- **界面**：客户详情 → 证件「编辑」→ 录入新 `expiry_date` → 保存 → 状态变「有效」
- **底层**：`PUT /clients/{id}/identifiers/{identifierId}` → Fineract

#### Step 8 · 手机银行：重新登录 → 拦截解除 → 交易成功（闭环）
- **界面**：横幅消失 → 再次转账 → 成功入账 → 明细出现新流水
- **底层**：过滤器读到新 `expiry_date` → 放行，Fineract 真正执行交易

### 2.2 目标状态的一句话总结

> **同一笔转账，证件过期时被拦、更新后成功** —— 这就是从「当前无法实现」到「目标状态已实现」的最强证明。
