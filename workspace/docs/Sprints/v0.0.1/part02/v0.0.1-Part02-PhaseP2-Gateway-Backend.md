## 背景与动机

网关是渠道层一切的中枢（ADR-005 铁律：前端永不直连 8443/8081）。P0 已把后端定型为生产形态（HTTP 8081，容器内网），网关 dev 形态直连本地生产形态栈联调——**网关到 Fineract 走 HTTP 内网，公网 TLS 终止在网关**（生产拓扑同构）。本 Phase 的三条硬约束：① 一切端点按冻结契约实现（一致性由 springdoc diff 校验闭环）；② 登录走 D2 简化口径（PBKDF2 + 自签 JWT，Bearer 形态贴近真实资源服务器，后续换 Keycloak 只动签发/校验层）；③ **基线零拦截代码**——POC 演示的增量就是新写一个 GlobalFilter + custom Business Step，插入点必须干净。

### 任务 P2.2 简化登录与 JWT（Bearer 形态） ✅（2026-11-08，VP2.2.1–VP2.2.5 全过）

**目的**：D2 口径的登录闭环。网关加载 `gateway_users.json`（P0.3 产物），PBKDF2 校验口令，签发 HS256 短时效 JWT（claim：`sub`=clientId（**admin 无 clientId 时 `sub`=username**，内部通道不依赖 clientId 反查）、`channel`∈{customer,internal}）；GlobalFilter 校验 `Authorization: Bearer`。效果 = 通道鉴权骨架成立（P3 换 Keycloak 只动此层）。

#### 改动详情

**新建文件**（`$GW/src/main/java/.../`）：

- `auth/UsersStore.java`（启动加载 `gateway_users.json`；路径 env `ABNK_USERS_FILE` 覆盖，默认指向 `$ABNK_REPO/data/gateway_users.json`——dev/bootRun 宿主路径；容器形态由 P3.4 Dockerfile 打包至 `/app/data/gateway_users.json` 并以 env 默认值注入，两侧路径契约在此声明）
- `auth/LoginController.java`（`POST /login`：username/password → 校验 → JWT 签发；错误 401 统一载荷。PBKDF2 校验按 P0.3 定死的跨端契约执行：`javax.crypto.SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256")` 手工比对——**勿用 Spring `PBKDF2PasswordEncoder`**（其内置 `{pbkdf2}` 前缀 + base64(salt‖hash) 单串格式与 JSON 分离字段不兼容，默认算法/迭代数也不透明）；演示口令从 `.github-private/` 归档处经环境变量注入测试，不入代码与证据）
