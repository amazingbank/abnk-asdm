### 已知环境坑

1. **git mv 目录两步法**：目录不能直接移入自身子目录——正确次序：`git mv workspace _ws_tmp && mkdir workspace && git mv _ws_tmp workspace/zh-CN`（在 `$ASDM` 下执行）；一步写成 `git mv workspace workspace/zh-CN` 会报 `invalid argument`/自引用错误。
2. **未跟踪件的判据口径**：`part03/` 5 个未跟踪文档随目录物理移动但不产生 rename 记录——status 判据必须区分 `R` 计数（67，tracked 迁移）与 `??` 计数（6 = part03 5 + en-US README 1），不能笼统「status 无变化」。
3. **asdm-training 甄别坑（最大误伤面）**：`$WS/asdm-training/` 下有自己的 `.asdm/toolsets/`——grep 全仓 `asdm/workspace` 会命中大量 training 仓自身引用；清扫范围必须限定**本仓物理路径**（`$ASDM` / `$ABNK`），判据命令不得写成全 `$WS` 扫描。
4. **`.codebuddy` 目录是项目数据**（不得删除/不得纳入清扫）——实测 0 命中 `.asdm/workspace` 引用，无需处理。
5. **相对链接不受整体迁移影响**：workspace 内文档间的相对链接（`./xxx.md`、`../planning/...`）随目录整体移动自动保持有效——只有 `.asdm/workspace/` 前缀的路径形态断链；清扫面以此精确界定，**不做全文档链接审计**（出界声明，见风险与备注）。
6. **`manifest.json` 是工具集事实源**：toolsets 的 config-driven 行为依赖其中的 workspace 路径——路径替换后必须做引用目标存在性全验（`V5.2.3`），不能只看 grep 清零。
7. **git mv 会把 rename 暂存入 index**：与「文档未提交、用户决定提交时机」惯例兼容（暂存 ≠ 提交）；执行前告知用户 rename 已入暂存区即可。

## 背景与动机

`.asdm/workspace` 是 ABNK 的规划/设计/发版/冲刺文档库（中文为主体），当前平铺在 workspace 根目录。D4 决策要求双语目录结构：`workspace/zh-CN`（现有内容整体迁入）+ `workspace/en-US`（骨架，内容按需单独处理）。迁移的连带面是全仓路径引用：toolsets 5 文件 17 处、`.asdm/README.md` 与 abnk-system 2 文件、workspace 内部自引用 5 文件 8 处——不清扫则工具集（doc-review/prod-deploy 的路径契约）、根 README 导航与交叉引用全部断链。

## 方案要点

1. **两步 git mv 保历史**：目录整体迁移（方案见已知坑 1），rename 检测保 72 文件的 blame/历史链；未跟踪件随目录物理移动。
2. **en-US 骨架最小化**（D4）：仅 `workspace/en-US/README.md`（英文，说明镜像约定：en-US 与 zh-CN 目录结构镜像、内容按需后补、新建文档的双语规范指向 Phase 6 的 check-bilingual 机制）；不建空目录树、不翻译任何存量内容。
3. **清扫以精确路径界定**：替换形态统一为 `.asdm/workspace/` → `.asdm/workspace/zh-CN/`（en-US 引用暂无）；范围 = 外部 9 文件（toolsets 5 + `.asdm/README.md` + abnk-system 2 + 根 README 树状图）+ 内部自引用 5 文件；**toolsets 只改路径串、内容零翻译零改动**（D4：内容不动）。
4. **判据分层**：grep 清零（断链消除）≠ 引用有效（目标存在）——`V5.2.1/V5.2.2` 管清零，`V5.2.3` 管存在性，`V5.2.4` 管 toolsets 纯路径替换声明（变更行全部含 zh-CN，防顺手动了内容）。
5. **`.asdm/README.md` 目录树同步**：根 README 的 workspace 树状图与速查表行随迁移更新（zh-CN/en-US 两层 + en-US 骨架说明），属引用清扫范围而非内容翻译。
