## 背景与动机

Phase 1 完成后 UI 文案已词条化，但两类「用户可见内容」仍写死中文：① api 层 13 处 `throw new Error('中文')`（mock/remote 双实现的业务异常 + `generatedClient.ts` 的 Axios 状态码映射兜底），经 5 处 `message.error` 直显给用户，英文界面下错误提示仍是中文；② mock 数据（客户姓名、产品名、证照名）为单语中文，无英文数据集（运营员 displayName 已为语言中性英文单值，2026-11-12 拍板，不属双语化对象），无法演示「部署期选择数据语言」的开源全球化口径。本 Phase 把错误消息改错误码 + 词条翻译、把 mock 数据拆双语两套并接通部署期选择。

## 方案要点

1. **错误码与词条解耦（分层纪律）**：api 层只抛错误码（`ApiError`：`code` + `params`），不依赖 i18n；UI 层经翻译 helper 按当前语言查 `errors` 命名空间词条。这样 remote/mock 双数据源行为一致，且 api 层可单测。
2. **错误码表（9 码，覆盖 13 处抛出点）**：
   | code | 替换点 | zh 词条 | en 词条（语义重写） |
   |---|---|---|---|
   | `auth.invalidCredentials` | `mockAuth.ts:24`、`remoteAuth.ts:25` | 用户名或口令错误 | Invalid username or password |
   | `client.notFound` | `mockClient.ts:48`、`remoteClient.ts:149/216` | 客户不存在：clientId={clientId} | Client not found (ID: {clientId}) |
   | `client.identifierNotFound` | `mockClient.ts:62`、`remoteClient.ts:248` | 证照不存在：clientId={clientId} identifierId={identifierId} | Identifier not found (client {clientId}, identifier {identifierId}) |
   | `network.offline` | `generatedClient.ts:66` | 网络连接失败，请稍后重试 | Network unreachable — please try again shortly |
   | `auth.sessionExpired` | `generatedClient.ts:69`（401 兜底） | 登录已失效，请重新登录 | Your session has expired — please sign in again |
   | `auth.forbidden` | `generatedClient.ts:72`（403 兜底） | 无权限执行该操作 | You are not authorized to perform this action |
   | `resource.notFound` | `generatedClient.ts:75`（404 兜底） | 请求的资源不存在 | The requested resource does not exist |
   | `server.error` | `generatedClient.ts:77`（params: `{status}`） | 服务异常（{status}），请稍后重试 | Server error ({status}) — please try again shortly |
   | `unknown` | `generatedClient.ts:79` | 未知错误 | Something went wrong |
   `serverMessage` 优先级保留：网关 body 有 `message` → 原样透传（数据边界）；无 → 错误码。
3. **页面兜底词条沿用（Phase 1 已交付）**：3 处 catch 兜底词条 `loginFailed`/`clientDetailLoadFailed`/`identifierUpdateFailed` 已在 Phase 1 任务 1.6 落入 `errors` 命名空间并被页面消费（`errors.json` 双语词条实测存在）——本任务不新增 `page.*` 前缀键，catch 分支改 `message.error(apiErrorMessage(err, '<既有兜底码>'))`，翻译 helper 以兜底码收尾（键名沿用既有三键，避免孤儿词条）。`message.success` 两条插值文案（`IdentifierEditForm.tsx:56`、`LoginPage.tsx:22`）已在 Phase 1 词条化，本 Phase 不动。
4. **双语数据集 + 构建期选择**：`mockData/{zh-cn,en-us}/` 两套 JSON；`mockStore` 以 `import.meta.env.VITE_ABNK_DATA_LOCALE === 'en-us' ? en : zh` 静态三元选择（Vite 常量折叠 + tree-shaking → bundle 单数据集）。部署链：`deploy` env `ABNK_DATA_LOCALE` → Dockerfile `ARG` → 构建期 `VITE_ABNK_DATA_LOCALE` 注入（对齐 `VITE_ABNK_API_BASE` 烘焙先例，`Dockerfile:24`）。
5. **en 数据集是语义重写**（D2 同口径）：姓名/产品名/证照名按英语银行业惯用形态重写（如 `王POC-A1107104347` → 形如 `Alex POC-A`、`ABNK 活期储蓄` → `ABNK Current Savings`、`身份证` → `National ID`），非逐字转写；结构字段与 zh 完全一致。
6. **顺带收紧类型**：现状 `mockStore.ts:16`/`mockAuth.ts:15` 用 `as unknown as` 宽转换无校验——双语拆分时数据文件统一过 `satisfies` 结构校验（以 zh 为源类型），结构漂移在 typecheck 拦截。
7. **边界**：remote 模式数据来自 Fineract（真实服务端数据不翻译，D3）；`VITE_ABNK_DATA_LOCALE` 仅对 mock 数据集生效；mobile 侧对应改造在 Phase 4；prod 镜像在服务端构建（`abnk-prod-deploy` 铁律），本 Phase 只落注入链与 env 样例，不做服务端镜像构建验证（显式出界，见风险与备注）。
