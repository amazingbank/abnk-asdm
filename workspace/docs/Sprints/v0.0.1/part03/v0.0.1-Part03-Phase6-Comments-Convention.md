### 已知环境坑

1. **注释配对判定的两种合法形态**：同行 `// 中文说明 | English summary` 与相邻行（中文行在上、英文行紧随）——脚本与 6.1 人工口径都必须两形态都认，否则合法文件被误报。行内豁免标记 `# noqa-bilingual`（罕见场景：引用原文名言/专名注释）。
2. **`V6.3.1` 终检 grep 的范围界定是最大误报面**：zh 词条文件（`i18n/locales/zh-cn`、`l10n/app_zh.arb`）与 zh 数据集（`mockData/zh-cn`、`fixtures/zh-cn`）是**合法中文**（它们就是中文内容本体）——终检判据必须精确排除这些路径，否则必然误报「未清零」。
3. **工具集敏感件**：`$TOOLSET/secrets.local.json` 存在（生产敏感信息）——本 Phase 任何步骤不读取不修改；manifest 注册只动 `commands` 字段与 `version`。
4. **toolset 版本递增纪律**：`manifest.json` version 0.1.1 → 0.1.2（additive command 递增），只改 version 数字与新增条目，不翻译既有内容（D4 口径延续）。
5. **三载体条件门不可预判**：iOS/Android 模拟器状态执行时实测；不可用 → 记录挂账（对齐 Part02 任务 P3.6 ipa 段挂账先例），web 判据必须过、不因此阻塞 Part 收口。
6. **flutter drive 走查耗时与归档体积**：三载体两态截屏约数十张——归档 `$ART/carrier-walkthrough/` 目录约定，按 `{载体}-{语言态}-` 前缀命名（对齐 P1.3 截屏归档惯例）。
7. **macOS bash 3.2 兼容**：脚本不用 bash 4+ 特性（关联数组等），对齐 `count-loc.sh` 惯例。
8. **6.3 步骤的「复验」性质**：全流程走查的判据复用既有 Phase 步骤口径（如 `V1.6.4`、`V3.4.5`、`V4.2.6`）——不做新断言口径（防收口期临时放宽/收紧标准造成口径漂移）。

## 背景与动机

Phase 1–4 的执行规则已要求触碰文件注释双语化，但缺三样东西收口：①**全量核查**——各 Phase 分散执行，无统一矩阵证明触碰文件集双语注释完整（漏网无门禁可见）；②**防回潮机制**——规范只存在于文档规则里，后续贡献者无工具强制，中文单语注释会随增量开发回潮；③**Part 级验收**——两端中英切换从未在同一轮全流程走查（mobile 三载体走查在 Phase 3 显式出界、数据集切换在 Phase 2/4 分散验证）。本 Phase 一次性补齐三件事并回写 Plan 收口。

## 方案要点

1. **6.1 是审计不是重做**：Phase 1–4 规则 7 已在触碰时双语化——本任务产出「触碰文件 × 双语配对状态」核查矩阵（归档），发现漏网就地补；判据 = 矩阵无空格、配对缺口 0。
2. **脚本形态**（对齐 `count-loc.sh` 惯例）：`$ABNK/scripts/check-bilingual.sh`——输入目录/文件列表，提取含 CJK 的注释行（`//`、`///`、`/* *`、`#` 形态），按注释块判定双语配对（同行 `中文 | English` 或中文行 + 紧随英文行，两形态合法；`# noqa-bilingual` 豁免）；输出 markdown 违规表（文件:行号:内容）+ 总数，违规 > 0 → exit 1。
3. **工具集接入（additive）**：`$TOOLSET/actions/abnk-check-bilingual.md`（action 文档，英文骨架+中文括注的 toolset 既有风格）+ `manifest.json` commands 增 `abnk-check-bilingual` 条目 + version 递增 0.1.2——新增不改旧（D4「内容不动」延续）。
4. **CI 接入为登记口径**：`abnk-system/ci/README.md` 规划表增 check-bilingual 行（触发：每次提交；内容：脚本对 channels 两端源码）——`workflows/` YAML 本身尚未建设（CI 现状为规划级），实际流水线接入随 CI 首版落地（显式出界声明，非本 Phase 范围）。
5. **6.3 全流程走查 = 复验汇总**：两端双语切换全路径（UI 词条/错误提示/枚举映射/数据集解耦）+ mobile 三载体（web 必测、iOS/Android 条件门）+ 终检 grep + Plan 进度回写——判据全部复用既有 Phase 步骤口径（已知坑 8）。
6. **回写收口**：全部通过后 Plan「进度概要」状态列回写 ✅，`artifacts/part03/` 索引清单归档。
