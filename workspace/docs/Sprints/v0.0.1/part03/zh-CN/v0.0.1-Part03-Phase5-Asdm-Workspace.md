### 已知环境坑

1. **逐目录 git mv 的操作形态**：叶子层迁移不适用原「两步整树 git mv」——正确形态为对每个含创作文档的目录执行 `mkdir -p <目录>/zh-CN && git mv <目录>/*.md <目录>/zh-CN/`（per-directory mv，rename 检测同样 R100）；**同一命令内不要混入非 md 文件**（png/JSON 属证据资产，按方案要点 3 的规则归位）。
2. **中文文件名 quotepath 坑**：`git ls-files` 对非 ASCII 文件名默认引号转义（`core.quotepath=true`）——modelB 的中文文件名会以八进制转义形态输出，`comm`/`diff` 类判据必须加 `git -c core.quotepath=false`，否则 tracked 文件被误判为未跟踪（2026-11-15 实测发生）。
3. **p3-*.yaml 双份漂移坑**：工作区根的 7 个快照文件非 git 管理——拷贝入 `$SPRINTS/part02/artifacts/phaseP3/` 后，源文件保留至任务 5.3 清扫时删除（避免双份各自演化；删除前以源为审校对象）。
4. **跨仓迁移不保历史（有意取舍）**：`git mv` 不适用跨仓；artifacts 采用复制 + 来源记录（`$ABNK` HEAD `bd3cf62` 的 commit hash 写入迁移记录）。证据文件是执行快照非演进代码，blame 需求近乎为零——与 workspace 侧 R100 保历史是**两种不同口径**，勿混用。
5. **双份共存窗口**：任务 5.1（拷贝）与 5.3（删源）之间 abnk-system 与 `.asdm` 存在 artifacts 双份——窗口内以 `.asdm` 侧为审校与新事实源，abnk-system 侧只读不写；删源（`git rm`）在 5.3 的 V5.3.5 执行。
6. **执行输出跨仓落盘坑**：abnk-system 的 `scripts/`/`tests/` 输出路径（`../../artifacts/phase1/report-<ts>.json` 等 11 处，2026-11-15 审核复测）改为「本地输出 → 收口归档」两段式——脚本继续本地输出（gitignore 排除），任务收口时显式归档到 `$SPRINTS/partXX/artifacts/`；**不得**让脚本直接跨仓写 `.asdm`（git 工作区纪律）。
7. **`.DS_Store` 与 modelB**：`.DS_Store`（ignored）不入迁移对象；`planning/modelB/` 为外部资料汇编（语言无关），**不做叶子分层**——5.2 的判据必须显式排除，防误迁。
8. **part04 文档同期存在**：本方案同期新建的 `$SPRINTS/part04/` 文档（Plan + Phase1–5，共 6 件，2026-11-15 已扩至 5 个 Phase）——D9 修订批提交后为 tracked 新增件，属 5.2 叶子层迁移范围（一并 `git mv`）；若执行时 part04 文档尚未提交，则以未跟踪件口径随目录物理移动（对齐原 Phase5 已知坑 2 的口径处理，`??` 计数在判据中显式声明）。
9. **`git mv` 会把 rename 暂存入 index**：与「文档未提交、用户决定提交时机」惯例兼容（暂存 ≠ 提交）；front-matter 注入（5.4）要求与 rename **分两次提交**（提交纪律见方案要点 5）——暂存后先行提交 rename，再做注入变更。
10. **D9 修订批提交前置**：2026-11-15 的 D9 修订（Plan/Phase5/Phase6 扩名、part04 6 文档、ADR-010）当前在工作区未提交——「两仓工作区干净」判据与 V5.2.1 的 R 计数分母均以**本批提交后**为基线；执行 5.1 前先提交（提交内容与分组由用户确认，破坏性操作无——纯文档提交）。

## 背景与动机

`.asdm` 仓定位是过程资产仓，但过程证据（artifacts）物理上一直住在交付物仓 abnk-system；workspace 平铺无语言分层，D4 要求的双语结构尚未落地。Sprint v0.0.1 Part04（dev portal）立项后，数据管线（front-matter → index → 渲染）需要三个前置条件：证据与文档同仓且按 Part 自包含、结构树语言无关而文档按 locale 分层、markdown 携带机器可读元数据。本 Phase 一次性完成归仓、分层、注入三件事，并把 index 生成器移交 Part04——「数据源就绪」是本 Phase 的职责边界。

## 方案要点

1. **Part = 自包含交付单元**：证据与文档同处 `$SPRINTS/partXX/`——证据指针从跨仓路径（以 abnk-system 根为基准的 `artifacts/phaseX/...`）变为 Part 内相对路径（`./artifacts/...`），文档树内相对链接随目录整体迁移天然保全。分桶映射（实测 2026-11-15）：
   | 源（abnk-system/artifacts/） | 目标（$SPRINTS/） | 文件数 |
   |---|---|---|
   | `phase1/` | `part01/artifacts/` | 3 |
   | `phaseP0/` + `phaseP1/` + `phaseP2/` + `phaseP3/` | `part02/artifacts/`（保留 phaseP0–P3 子目录名，对应 Phase 编号） | 6+37+10+148 |
   | 工作区根 `p3-*.yaml`（7 文件） | `part02/artifacts/phaseP3/` | 7 |
   | `part03/` | `part03/artifacts/`（phase1–4/7 + poc-journey + seed-en 子目录保留） | 124 |
   | 根 `README.md`（入库纪律） | `artifacts/README.md`（Sprint 级兜底目录 + 归档纪律，无法归属 Part 的散件归此） | 1 |
   合计 336 文件（329 + 7）。
2. **locale 置于叶子层（D4 修订）**：结构树（part/planning 分区/sre 版本目录）语言无关；创作文档入 `zh-CN/` 子目录；**en-US 按需在叶子生长，路径与 zh-CN 对齐（路径即 doc id）**，en 为语义重写非镜像翻译（D2 延续），缺失即 fallback。适用范围（全量创作树）：Sprints 各 part、planning/abnk-design 各分区 + adr、sre/ReleaseNotes 各版本。**永不分层**：`artifacts/`（证据语言无关——en 渲染复用同一物理证据）、`planning/modelB/`（外部资料）。
3. **en-US 生长规则约定**：`workspace/docs/README.md` 声明四条——①en 文档存在时路径与 zh-CN 对齐；②en 是语义重写（D2），允许 en 侧有 zh 没有的文档、允许缺失；③en 文档「已注册」的标志是 index 层条目（Part04 生成器产出）；④证据资产语言无关，物理位置随源文档树。
4. **引用清扫终态**：三个面合并一次清扫——A 面（workspace 旧路径，**仅文件级引用替换**——指向具体文件的路径改含 `zh-CN` 段的新路径，插入位置按树类型路由：Sprints 树插在 partXX 后、planning 树插在分区后、sre 树插在版本目录后；**目录级引用**（如 `.asdm/workspace/docs/Sprints/`、`docs/planning/`——结构树语言无关，迁移后目录路径仍有效）与**叙事性提及**（决策记录/泛指文字）豁免，口径判据化见 V5.3.1；**跨目录相对链接深度 +1 同步改写**——md 内 `](../...)` 形态实测 7 处（均为 ADR-010 链接，链接目标同时迁入 zh-CN））；B 面（`.asdm` 创作文档内跨仓 artifacts 引用，替换为 Part 内相对路径——创作树口径与豁免见 V5.3.2）；C 面（abnk-system 侧：`git rm -r artifacts` + scripts/tests/README 11 处输出路径改两段式声明）。**toolsets 引用直接指向 zh-CN 物理路径**（工具消费源语言工作文档，人/AI 跟随路径零间接——语言无关性只属于 index 层；toolsets 内目录级表述（如 `.asdm/workspace/docs/Sprints/`）保持原样——目录树语言无关）。
5. **front-matter 注入 + 提交分离**：全 workspace 创作 markdown（67 tracked md + part04 6 + ADR-010 1 + 5.2 新建 `workspace/docs/README.md`——不含 artifacts 证据 md 与 modelB，口径见任务 5.4 改动详情）头部插入 YAML front-matter；三 profile——`sprint-doc`（sprint/part/phase/status/date/evidence/locale/doc-note/moved_to）、`planning-doc`（section/status/locale）、`release-note`（version/date/locale）。**提交纪律**：commit A 纯 rename（零内容变更，R100 完美）与 commit B 注入（内容变更，blame 整体位移一次，`git log --follow` 语义清晰）分离；注入可独立 revert 不牵动迁移。状态工作流自本 Phase 起：任务勾选同时改 front-matter 的 status 字段（正文 emoji 保留为渲染形态）。
6. **凭据扫描门**（ADR-010 衍生约束 2/5）：拷贝前对 336 文件全量跑（机械模式：口令/token/密钥字面量、`.github-private` 内容引用、真实公网 IP 字面量→域名替代）；Part02 既有纪律（「演示口令 grep 0 命中、token `<redacted>`」）作为基线预期。扫描不是脱敏审计门——拓扑/端口/流程描述**不处理**（透明是叙事本体）。

5. 状态标注：任务执行前为「⏳ 待执行」，全部步骤通过后改「✅ 已完成」。
6. **本 Phase 无编译门槛**（纯资产层）：判据全部为静态 grep/test/计数；**回滚预案**——任务 5.1 拷贝为纯增量（删目标即回退）；5.2 为反向 git mv + 引用反向替换；5.3 删源以 git 历史回退（`bd3cf62` 之后 revert）；5.4 注入独立 revert。
