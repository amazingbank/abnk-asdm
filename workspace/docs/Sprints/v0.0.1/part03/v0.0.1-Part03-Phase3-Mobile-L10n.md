### 已知环境坑

1. **intl 版本配套**：`flutter_localizations` 与 `intl` 版本由 SDK 严格配套——`intl` 用 `any` 让 pub 解析配套版（手动钉版本撞 SDK 内置版本时表现为莫名的 localizations 编译错）。
2. **template 反转是本仓特例**（D2）：Flutter 生态惯例 template 为 en，本仓有意用 `app_zh.arb` 为 template（中文为源）——生成器对 en 缺 key 会静默以 template 文案兜底并输出 untranslated 警告，**必须**靠 `V3.1.3/V3.1.4` 的 untranslated 检查 + key 集比对把关，不得只看生成成功。
3. **widget 测试默认 locale 是 en_US**：`testWidgets` 环境 `AppLocalizations.of(context)` 在 delegates/locale 未配置时抛错或空——测试 pump 必须显式携带 `localizationsDelegates` + `locale: Locale('zh')`（词条断言统一 zh 态）。
4. **shared_preferences 测试形态**：widget/单元测试中必须先 `SharedPreferences.setMockInitialValues(...)`（否则 `MissingPluginException`）；web 载体上实现为 localStorage。
5. **生成物不入 git**（**口径修正 2026-11-12**：Flutter 3.47 已移除合成包，gen-l10n 产物随 arb-dir 输出到 `lib/l10n/app_localizations*.dart`，delegate 内嵌于主文件，导入路径 `l10n/app_localizations.dart`；`.gitignore` 已加规则）——构建会自动跑，但词条改动后的验收步骤必须**显式**执行 `flutter gen-l10n`（不依赖 build 副作用）。后续 `V3.4.2` 中文清点判据须排除生成物文件（`app_localizations*.dart` 为机器产物，非手写文案）。
6. **页签重建与 locale 重建正交**：`main_scaffold.dart:27-33` 的 `IndexedStack` 用 `ValueKey('home-$_currentIndex')` 控制页签重拉；locale 切换经 `MaterialApp` 整树重建（`app.dart:20-21` ListenableBuilder）——`MainScaffold` State 同位保型，当前页签索引不丢（走查时顺带断言）。
7. **pubspec 改动后先 `flutter pub get`**：gen-l10n/analyze/test 都依赖依赖解析完成，顺序不得颠倒。
8. **web 载体首启编译等待**：`flutter run -d chrome` 首次编译约 30s+，判据 = DevTools/console 出现应用就绪输出后再执行走查动作（P1.3 惯例）。

## 背景与动机

mobile-banking 当前零 l10n 机制：`app.dart:22-27` 的 `MaterialApp` 无 `localizationsDelegates`/`supportedLocales`，title 写死中文（`:23`）；lib 约 119 行用户可见中文字面量（7 页面 + 布局壳 + 3 个 model 枚举 label getter + 异常体系默认消息）；英文用户看到的 Material 内建组件文案也只有英文默认（无 delegates 时跟随 SDK 兜底）。作为面向全球开发者的开源项目三载体之一，需要与 backoffice（Phase 1/2）同等的中英切换能力，且共用同一套决策口径（D1 跟随系统 / D2 en 语义重写 / 部署期数据切换留给 Phase 4）。

## 方案要点

1. **官方零第三方 l10n 链路**（D7）：`flutter_localizations`（sdk）+ `intl` + `generate: true` + `l10n.yaml`；template 为 `lib/l10n/app_zh.arb`（中文为源，D2 有意反转生态惯例），`app_en.arb` 为语义重写译本。生成物 `AppLocalizations`（合成包），不手改。
2. **locale 状态复用既有链路**（D7）：`AppState`（`app_scope.dart:13`）增 `Locale locale` + `Future<void> setLocale()`（写 shared_preferences + `notifyListeners()`）——`app.dart:20-21` 的 `ListenableBuilder` 包住 MaterialApp，`notifyListeners` 即整树重建，零新增状态管理依赖；不引入 provider/riverpod。
3. **初始语言（D1）**：`main` 异步启动（`WidgetsFlutterBinding.ensureInitialized` + `SharedPreferences.getInstance`）→ 存储合法值优先 → 否则 `PlatformDispatcher.instance.locales` 任一 zh 开头 → `zh`，否则 `en`；locale 命名小写 `zh`/`en`（D8，Flutter Locale 简码）。
4. **MaterialApp 接线**：`localizationsDelegates: AppLocalizations.localizationsDelegates`、`supportedLocales: AppLocalizations.supportedLocales`、`locale: state.locale`、`title` 改 `onGenerateTitle` + l10n 词条。**口径修正**：Material 内建文案（日期选择器/tooltip 等）由 delegates（`MaterialLocalizations`）提供，`ThemeData` 无 localizations 参数——Plan 任务 3.2 标题中「ThemeData localizations」按此修正理解（见风险与备注）。
5. **消费惯例**：页面统一 `final l10n = AppLocalizations.of(context)!;`，词条 key 英文语义化驼峰（对齐 backoffice JSON 词条口径）。
6. **枚举映射函数化**：`transaction.dart:33-38`（typeLabel）、`identity.dart:37-41`（statusLabel）、`loan.dart:41`（等额本息）的 label getter 改为接收 `AppLocalizations` 的顶层函数/extension（models 保持零 BuildContext 依赖，label 决策上移到 UI 层）。
7. **异常码化（对齐 Phase 2 模式）**：`app_exception.dart` 五类默认中文消息 → 语义码（`err.network`/`err.auth`/`err.forbidden`/`err.server`/`err.validation.*`）；`AppExceptionPresenter.present(error, l10n)` 增 l10n 参数按码查词条；`generated_client.dart:65-71` 四条中文兜底 → 码化，**`serverMessage` 透传保留**（网关 body message 是服务端数据，原样显示不翻译——与 backoffice `V2.1` 同一边界）；mock 层 8 处 `ValidationException('中文')` → 码化（`ValidationException` 增码/参数形态）。
8. **测试适配口径**：8 个测试文件统一 pump zh 态（delegates + `Locale('zh')`），`find.text` 断言改 arb 词条值——测试继续以中文断言（zh 是源语言），不双语双跑（en 态覆盖由 3.2 新增的 locale 切换测试承担）。
9. **出界边界**：mock 层 note 兜底数据串（`mock_account_repository.dart:170/176`「本人账户转账」、`:211`「定期开户」）是数据文案，随 Phase 4 fixtures 双语数据集处理，本 Phase 不动（`V3.4.2` 硬门判据按此精确放行 3 行残留）。
10. **en 词条一律语义重写**（D2 铁律，如「等额本息」→ amortizing loan with equal monthly installments）。

### 任务 3.2: AppState 增加 locale + shared_preferences 持久化，MaterialApp 接线 localizationsDelegates

**目的**：l10n 骨架尚未接管任何渲染路径（MaterialApp 无 delegates、locale 状态无处存放）；本任务把 locale 接入 `AppState`（既有 ChangeNotifier 链路，`notifyListeners` 即整树重建）、shared_preferences 持久化、系统语言跟随、MaterialApp 三件接线——语言成为应用内可读可写的单一事实。

## 风险与备注

- **「ThemeData localizations」口径修正**：Plan 任务 3.2 标题沿用了早期探查的说法；实际 `ThemeData` 无 localizations 参数，Material 内建文案由 `localizationsDelegates`（`MaterialLocalizations`）提供——本 Phase 文档按修正口径执行，Plan 标题已同步更正。
- **三载体走查出界**：本 Phase 界面验收统一走 web 载体（逻辑层与载体无关）；iOS/Android 载体 `flutter drive` 截屏走查归 Phase 6 任务 6.3 全流程验收（对齐 P1.3 三载体惯例，不在本 Phase 重复）。
- **mock note 数据串出界**（`V3.4.2` 精确放行 3 行）：属数据层兜底文案，Phase 4 随 fixtures 双语数据集一并处理——判据故意精确到行号，防止「清零口径」与「数据边界」混淆。
- **arb placeholder 与插值**：金额/到期日/ID 插值统一用 gen-l10n placeholder（`{amount}` 等，`@` 条目声明 type），不拼字符串——对齐 backoffice `interpolate` 口径。
- **`AppLocalizations.of(context)!`**：非空断言是仓内消费惯例（MaterialApp 已全局挂 delegates，运行时不可能 null）；测试环境见已知坑 3。
- **`intl: any` 不升级为钉版**：配套解析由 SDK 保证（已知坑 1），钉版反而引入冲突面。
- **本 Phase 不动**：fixtures/*.json（Phase 4）、repository_factory 数据模式切换、ios/android 原生层（App 名 "ABNK" 保持一致，Part03 Plan 已定不做原生层切换）、生成 client 契约面。
