## 12 步链路（实测通过的端到端形态）

办公室 → 职员 → 客户（建+激活）→ 储蓄产品（积数计息形态：dailybalance + 360 天基）→ 开户（审批+激活）→ 存款/取款 → 贷款产品（等额本息）→ 申请（审批+发放）→ 部分还款 → 推进业务日期 → 触发日终 COB（`LOAN_COB`/inline）→ 关户负向断言。

## 两项原判推翻（对 Phase 2 的直接输入）

1. **积数计息原生支持**——`interestCalculationType=dailybalance(1)` + `daysCalculationInYear=360` 即中国积数法形态，产品配置即够，无需 custom 计提模块。
2. **对年对月对日原生支持**——12 期到期日 2026-11-24 → 2027-10-24 逐月对日，还款计划生成器无需定制。

→ Phase 2 的 custom 工作量随之缩减（planning 层 `05-domains/savings.md` §5、`05-domains/lending.md` §5 已同步回填）。
