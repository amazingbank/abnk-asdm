### 已知环境坑

1. **en 是语义重写不是翻译**（D2 铁律）：按英语母语者与行业惯用语组织句子（「等额本息」→ amortizing loan with equal monthly installments 先例）——逐字直译形态在 V2.3.2 有抽查判据（机翻腔关键词黑名单：杜绝「The following is…」式开头滥用与逐词对应句）。
2. **方法论改写的来源纪律**：asdm-training 是培训体系仓（含售前/客户场次物料）——改写只取**公开课与体系总纲**素材（`sessions/20261030-ISS-Public/`、`workshops/README.md`、`tracks/` 目录），**不引用**客户专属场次内容（KBank POC/SDIC 简报属项目交付素材，引用需裁决）；每篇改写文头注明素材来源路径。
3. **portal-content 的 locale 叶子层**：分区结构与 Sprints 同规则（`methodology/zh-CN/*.md` + `methodology/en-US/*.md`，路径即 doc id）——**不要**在 portal-content 顶层建 en-US 镜像树（D4 修订口径统一）。
4. **生成器 en 增量是双侧契约变更**：index 的 locale 字段语义从「恒 zh-CN」变「zh-CN/en-US 枚举 + fallback 标记」——`schema.ts` 同步改（V1.2.3 互证口径延续）；生成器与契约单独提交，便于回退。
5. **内容体量克制**（D6 诚实性在内容侧的体现）：en 第一批只做核心三页（overview 首页导览 / methodology 概览 / timeline 骨架说明），深链内容 zh 优先 + fallback 声明——**不**全面翻译 portal-content。
6. **三合一门对 md 的管辖范围**：front-matter 模式管结构（必填字段），**不**管内容双语（内容双语由 en-US 内容政策承载）——勿把「zh 单语 md」误报为违规（Part03 Phase 6 已知坑同源）。

## 背景与动机

portal 八大板块中，迭代时间线/证据链/E2E 旅程/指标四块是纯渲染（消费 Phase 1 数据集），但方法论板块是唯一需要新创作的叙事（社区读者需要知道 ASDM 是什么、三大工程指什么才能理解他们看到的迭代记录的含义）；治理板块需要 ADR 导读（把 10 条决策串成「为什么这个项目长这样」的故事）；而 dev portal 面向国际社区——en-US 内容的「按需后补」在此触发。三块内容全部落 abnk-asdm 仓 portal-content 分区：portal 仓保持零内容生产（D7 单一事实源），内容资产与 Sprint 资产同受 front-matter/三合一门管辖。

## 方案要点

1. **内容分区（portal-content）**：`workspace/docs/portal-content/{overview,methodology,governance}/`，分区内 locale 叶子层；front-matter 复用 `planning-doc` profile；方法论素材只取公开课与体系总纲（已知坑 2）。
2. **IA 映射表是消费侧单一事实源**：八大板块（方法论 / 规划与决策 / 迭代时间线 / 任务证据链 / E2E 旅程 / 指标仪表盘 / 治理与开放 / 复现指南）× 三列（数据源路径 / 渲染模式 / 责任 Phase）——Phase 3 每个页面任务开工前对照本表，防板块漂移。
3. **en-US 第一批 = 生长规则首次实践**：三个 doc id 在 en-US 侧落地 + 生成器 locale 路由增量（en 条目注册 + fallback 标记）+ 契约同步——之后 en 内容按同一机制增量生长，不再有专门「翻译 Phase」。
4. **内容验收三层**：结构层（front-matter 合法 + 生成器消费成功）→ 语言层（en 抽查语义重写质量）→ 纪律层（三合一门走查 + 素材来源标注核验）。

## 任务分解

**执行规则（全任务生效）**：

1. 步骤必须实际执行并记录真实输出；跳步、肉眼过内容，均不算通过。
2. **任务门禁**：任务按 ID 顺序执行；当前任务全部步骤通过并勾选后，下一任务方可开始；任一步骤失败即停，修复后从该步骤重跑。
3. **步步有验收**：每个步骤紧跟可执行的验证动作（命令 → 期望输出）；内容类步骤的验收 = 结构判据（front-matter/生成器/门）+ 归档记录（内容清单 + 抽查结论，无空单元格）。

6. **编译门槛铁律**：契约/生成器改动后 `npm run typecheck`（portal 侧）+ 生成器三判据复验；纯 md 创作后跑生成器 `--verify`。
7. **双语注释铁律**：本 Phase 触碰的脚本/配置注释一律中文在上、英文语义重写在下；新增 md 一律 front-matter 正向书写。
