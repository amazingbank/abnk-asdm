### 已知环境坑

1. **front-matter 现实漂移**：Phase 5 注入后，若有人手改 Plan 表而未改 front-matter（双源漂移），生成器必须 **fail-loud**（报错退出而非静默跳过/降级）——这是「数据可信度」的门，V1.1.7 有专门演示判据；不设计任何「容错跳过」路径。
2. **两侧 git 纪律相反**：`$INDEX` 产出物**入库**（git history 即审计记录，不得 gitignore）；`$PORTAL/src/data/` 拷贝产物**不入库**（构建时生成，必须 gitignore）——两套纪律相反，脚本与 .gitignore 各自写死，勿混。
3. **生成器语言选型**：front-matter YAML 解析不用 bash 手撕（正则容差坑），用 python3 `yaml.safe_load`（与 Part03 Phase 5 注入脚本共用解析口径——同族脚本，口径漂移 = 互证失败）；脚本骨架仍按 `count-loc.sh` 惯例（用法头 + 幂等 + 明确退出码）。
4. **clone 位置不可变**：`$PORTAL` 必须在 `$WS` 容器内与 `$ASDM` 并排——构建脚本 `sync-data.sh` 用相对路径（`../.asdm/workspace/...`）取数；放别处 = 构建脚本路径断裂（对齐 `.asdm/README.md` 对 abnk-system 克隆位置的同类约束）。
5. **npm 而非 pnpm/yarn**（全仓惯例）：骨架的 run scripts 与判据命令一律 npm 形态。
6. **指标第一批清单固定**（Phase 3 仪表盘直接消费，不在本 Phase 扩范围）：VP 判据达成（Part02 34/34 等）、单测/断言/DRIFT 计数（57/57、55/55、0）、LOC 与规模曲线（count-loc.sh）、Sprint 节奏（Phase 起止日期差）、挂账/移交计数、ADR 数、evidence 密度、CI 状态如实标注「未实跑」——**没有的指标不虚构**（D6 诚实性铁律在数据层的体现）。
7. **devportal 仓 init 的首个提交内容**：骨架 + 契约 + 构建脚本（不含 `src/data/`——坑 2）；README 声明定位（纯渲染器、D7 约束）与两仓并排 clone 前置（坑 4）。

## 背景与动机

Part03 Phase 5 完成了「数据源就绪」（front-matter 全覆盖、证据 Part 分桶、locale 叶子层），但消费侧为零：元数据仍需逐文档解析、指标散在测试报告正文、portal 仓为空。本 Phase 补齐生产与消费两端：生成器把 front-matter 翻译成结构化 index/metrics（入库可审计），portal 骨架建立「只读复制 → 构建」的最简数据链（任何机器 checkout 两仓可复现），脱敏终审守住公开边界——「数据就绪、契约锁定」，页面渲染（Phase 3）与内容创作（Phase 2）在此之上开工。

## 方案要点

1. **生成器 = abnk-asdm 的自审工具**（D4「提取入库」）：`$ASDM/scripts/gen-sprint-index.py`——遍历 `$SPRINTS` 的 front-matter 生成 `$INDEX/sprint-v0.0.1.yaml`（Sprint→Part→Phase→Task→status→date→evidence 骨架）+ `$INDEX/metrics-v0.0.1.json`（已知坑 6 清单口径）；三重校验内建：index vs front-matter 零漂移、metrics vs 源报告零漂移、解析失败 fail-loud；幂等（重跑零变更）。
2. **契约 = 编译期锁定**：`$PORTAL/src/data/schema.ts` 定义 index/metrics 的 TS 类型（`satisfies` 编译期校验，对齐 i18n 同构惯例）——portal 对数据形态的所有假设集中在这一处，Phase 3 页面只消费类型不解析原始 md。
3. **构建链 = 只读复制**：`$PORTAL/scripts/sync-data.sh`——从 `../.asdm/workspace/{index,docs/Sprints,docs/planning/abnk-design}` 只读复制到 `src/data/`（index JSON + md 全文 + 证据素材索引）；判据含「源仓 status 零变化」（只读性证明）；portal 构建零提取逻辑（D4）。
4. **复刻而非新建**：工程骨架第三次同构复刻 abnk-website（Vite + React + TS + Tailwind + i18n 8 模块 + design tokens env 覆盖）；D7 约束写入 README（纯渲染器，不长运营功能）。
5. **脱敏终审 = 双通道**：机械通道（`check-bilingual.sh --credentials` 对 `$PORTAL/src/data/` 全量；Phase 6 未落地时以同口径 grep 代跑并归档）+ 人工通道（抽样复核 + 处置记录）；通过是 Phase 2/3 消费该数据集的前置门。

## 风险与备注
