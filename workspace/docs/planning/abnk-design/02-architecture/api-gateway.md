# API 网关（渠道层）

> **性质**：设计框架（Phase 3 启动时细化）。已定约束来自 ADR-005；API 事实来自 `00-baseline/api-surface.md`。

---

## 1. 存在理由（三个都必须）

1. **安全边界**：前端永不直连 Fineract 8443（ADR-005 硬约束）；公网渠道（网银/手机）必须经网关做 OAuth2 鉴权与限流
2. **PoC 风险隔离墙**：Fineract API 变化（含 custom 模块机制演进）被网关吸收，前端无感（ADR-002 的缓解措施）
3. **契约收敛**：Fineract 的 603 端点是为全能管理台设计的；对客渠道只应暴露收敛后的子集 + 脱敏后的字段

## 2. 职责清单

| 职责 | 说明 |
|---|---|
| 路由 | `/abnk/api/...` → Fineract `/fineract-provider/api/v1/...`（内部路径不可见） |
| 鉴权 | 外部渠道 OAuth2/OIDC；内部渠道复用或转换 Fineract Basic/permission |
| 租户注入 | 网关按登录上下文注入 `Fineract-Platform-TenantId`（客户端不可伪造） |
| 字段收敛/脱敏 | 客户姓名/证件号按渠道策略脱敏（`personas.md` 约束） |
| 限流与配额 | 按渠道与客户端分级 |
| 审计 | 全请求日志（对接观测栈 Loki） |
| 编排 | 简单聚合（多端点拼装）放网关；**含审批流的业务编排放外围服务，不进网关** |

## 3. 明确不暴露的 Fineract 面（实测存在但面向运维/诊断）

- `/v1/internal/*` 全部 21 个端点（审计查询、COB 快进、贷款锁、配置覆写）——**生产网关黑名单**
- `/v1/jobs/*`（作业管理）→ 仅管理后台经内部通道可达
- `/v1/configurations/*` → 同上
- `/fineract.json`（完整 OpenAPI）→ 内部开发用，不对客

## 4. 技术选型（Phase 3 开项时评审，当前只列候选）

候选：Spring Cloud Gateway / APISIX / Kong。选型判据：OIDC 成熟度、多租户注入的插件成本、与观测栈（Tempo 追踪）集成。

## 5. 与三套前端的映射

| 前端 | 网关入口 | 鉴权 | 可达面 |
|---|---|---|---|
| 管理后台 | 内部域名 | 内部 SSO | 全量（含作业/配置） |
| 柜面 | 内部域名 | 柜员账号 | 柜员权限子集 |
| 网银/手机 | 公网域名 | OAuth2/OIDC（Keycloak 候选） | 收敛后的对客子集 |

## 6. 里程碑（对齐 roadmap）

- Phase 3 启动：网关 MVP（路由+鉴权+租户注入）与管理后台同批交付
- Phase 3 末：柜面接入
- Phase 4：公网渠道开放（安全评审为前置门）
