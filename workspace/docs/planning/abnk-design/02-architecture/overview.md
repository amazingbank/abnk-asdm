# 架构总览：L1–L5 分层

> **性质**：设计文档。分层事实依据：`00-baseline/`（Fineract 能力与扩展点）、ADR-001~006。

---

## 1. 分层图

```
┌─────────────────────────────────────────────────┐
│ L5 智能层     AOS 代码本体 │ 数仓 │ AI 应用        │  ← 长期差异化
├─────────────────────────────────────────────────┤
│ L4 外围层     Kafka 事件总线 │ 支付 │ 征信 │ 风控 │ 报送
├─────────────────────────────────────────────────┤
│ L3 渠道层     API 网关 ── 柜面 │ 网银/手机 │ 管理后台
├─────────────────────────────────────────────────┤
│ L2 定制层     custom/abnk/（product/localization/integration/report）
├─────────────────────────────────────────────────┤
│ L1 本地化     COA │ 计息 │ 证照 │ 币种/时区（多为数据与配置）
├─────────────────────────────────────────────────┤
│ L0 核心层     Apache Fineract（fork，零修改，ADR-001）│
└─────────────────────────────────────────────────┘
        PostgreSQL 单宿主（ADR-003）· 多租户分库（ADR-004）
```

## 2. 各层职责与边界

| 层 | 职责 | **不做** | 关键文档 |
|---|---|---|---|
| L0 核心 | 账务、计提、日终、多租户 | 不改源码（唯一例外见 ADR-002） | `00-baseline/fineract-codebase.md` |
| L1 本地化 | 会计科目、计息习惯、证照 | 不写引擎逻辑，以配置+数据为主 | `05-domains/accounting.md` |
| L2 定制 | custom 模块代码 | 不碰核心表；只走 custom-changelog | `customization-strategy.md` ★ |
| L3 渠道 | 网关聚合、三套前端 | 前端永不直连 8443；不暴露 /v1/internal | `api-gateway.md` |
| L4 外围 | 事件消费、外部系统集成 | 不直写核心库，只经 API/事件 | `event-bus.md` |
| L5 智能 | 本体、数仓、AI | 只读事件流与数仓副本 | `aos-integration.md` |

## 3. 依赖方向（硬规则）

```
L0 ← L1 ← L2 ← L3 ← L4/L5（单向，上层依赖下层，永不反向）
```

- 上层只能通过 **L0 的 API** 或 **L4 的事件流** 获取核心数据
- 任何跨层直连（如前端直连 8443、外围直读业务库）= 架构违规
- 唯一的库级例外：监管报送/数仓读**只读副本**（Phase 4+ 定义）

## 5. 风险与总对策

| 风险 | 层 | 对策 |
|---|---|---|
| custom 模块 PoC 破裂 | L2 | 定制面收窄 + 网关屏蔽 + 季度 rebase 检查（ADR-002） |
| 上游 API 变化 | L3 | 网关做版本收敛，前端不感知 |
| 核心能力缺口 | L0 | 先查官方文档与 E2E，确认缺再考虑 custom，最后才是 fork |
| 事件丢失 | L4 | Kafka 持久化 + 消费者幂等（Phase 4 设计） |
