# 安全与合规

> **性质**：设计框架（Phase 3/4 分阶段落地）。现状事实：Basic Auth + 租户头（实测开箱即用）；OAuth2/2FA 端点存在但默认关闭。

---

## 1. 安全演进路线

| 阶段 | 鉴权 | 说明 |
|---|---|---|
| Phase 1–2（现状） | Basic `mifos:password` + 租户头 | **仅限本地调试**；风险已知（明文弱凭据） |
| Phase 3 | OAuth2/OIDC（Keycloak 候选） | Fineract `fineract.security.oauth2.enabled` 打开（与 Basic 互斥）；网关层做 OIDC，内部服务间凭证收敛 |
| Phase 3+ | 公网渠道安全基线 | 渠道分层限流、防重放、设备指纹（网关职责，见 `api-gateway.md`） |

## 2. 合规义务地图（Phase 4 前建立框架）

| 域 | 义务 | ABNK 落点 |
|---|---|---|
| 反洗钱 | 大额/可疑交易报告 | 事件总线订阅方（实时规则）→ 报送 |
| 监管报送 | EAST（银保监）、1104（人行口径） | `05-domains/regulatory-reporting.md` |
| 数据安全 | 个人金融信息保护（分级/脱敏/留存） | 网关脱敏 + DB 加密策略 + 日志规范 |
| 等保 | 网络安全等级保护 | 基础设施层（部署设计，另立 ADR） |
| 审计留痕 | 操作可追溯 | **CommandSource 已原生满足核心账务**；外围操作走网关审计日志 |

## 3. 已识别的技术安全项

| 项 | 现状 | 处置 |
|---|---|---|
| 自签证书（keystore.jks/openmf） | 调试用 | 生产换正式证书（部署 ADR） |
| `root` 数据库账号 | 调试三方对齐（ADR-003） | 生产专用最小权限角色 |
| `/v1/internal/*` 21 端点 | 面向运维/诊断 | 网关黑名单（`api-gateway.md` §3） |
| 业务日期可被 API 操纵 | 实测可设置 | 网关/权限层限制到运维角色 |
| 租户头客户端可伪造 | 直连时代无防 | 网关注入（`api-gateway.md` 职责表） |

## 4. 合规数据原则（提前约束设计）

- 证照号等 PII：存储加密列 + 展示脱敏 + 日志禁止全量打印
- 数据留存与删除：报送留存期 > 营销留存期——**数据分级从 custom 表设计第一天就做**（`datatables-vs-custom-tables.md` 附表登记数据级别）
