# 支付域（Phase 4）

> **性质**：骨架（Phase 4 开项时细化）。三段式结构预留，当前以集成面盘点为主。

---

## 1. 集成面（外部系统，全部为外部依赖）

| 通道 | 角色 | 集成形态 |
|---|---|---|
| 网联 | 银行账户与非银支付机构间清算 | 报文网关（专线），对账文件 |
| 银联 | 卡组织清算 | 接口 + 对账 |
| 人行支付系统（大额/小额/超网） | 行间清算 | 报文 + 清算窗口 |
| 内部账务 | Fineract | **唯一写入口 = Fineract API**（经事件总线触发） |

## 2. 架构定位（对齐 `overview.md` 依赖方向）

```
外部通道 ──▶ 支付适配服务（L4）──▶ Fineract API（L0，记账）
                │
                └──▶ Kafka（事件总线）：支付结果广播给风控/通知/数仓
```

- 支付适配是**外围服务**，不是 custom 模块（外部报文协议与核心无关）
- 记账唯一入口是 Fineract API——支付服务**永不直连业务库**

## 3. 已知差距（待 Phase 4 分析）

| 差距 | 说明 |
|---|---|
| 对账机制 | Fineract 原生无银联/网联对账文件处理——外围自建，差异经命令通道调账 |
| 支付渠道限额/风控 | 网关+风控服务职责 |
| 冲退/退货 | Fineract 有 reversal 概念（command 通道），映射规则待设计 |

## 4. 里程碑依赖

- 前置：事件总线（`event-bus.md`）、网关（`api-gateway.md`）
- 触发条件：第一波产品线稳定运行 + 对客渠道开放（Phase 3 出口）
