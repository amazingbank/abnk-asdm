## 1. 总览

**ModelB@nk** 是神州信息（神州数码信息服务股份有限公司，000555.SZ）自 **2000 年**首创并持续迭代发布的"**未来银行整体架构蓝图**"，是国内最早、影响力最大的银行 IT 整体架构方法论品牌。截至 2026 年已发布 **5 代**，当前主力版本为 2021 年 8 月发布的 **ModelB@nk5.0**。

| 维度 | 内容 |
|------|------|
| 品牌归属 | 神州信息（dcits.com） |
| 首创时间 | 2000 年（ModelB@nk1.0） |
| 当前版本 | ModelB@nk5.0（2021-08-12 于"TECH数字中国2021技术年会"发布） |
| 技术特性 | 数云融合 |
| 架构命名 | 主体架构官方命名为 **S.T.A2.R.S**（崔蕾《银行家》专题"图1 ModelB@nk5.0 主体架构：S.T.A2.R.S"，对应五层架构，各字母官方拆解未见公开文字版） |
| 核心构成 | 五层架构体系 + 三大支柱（技术中台、数据中台、金融超脑） |
| 体系定位 | 与"神州信创云"（2021-08 发布的全家桶架构蓝图）共同构成神州信息**"金融科技 2.0 架构体系"的两极**——ModelB@nk5.0 为应用层蓝图，神州信创云为基础层底座（来源：2021 年度报告） |
| 市场地位 | 神州信息核心业务系统市场份额连续 14 年（截至 2025）蝉联 IDC 第一；服务海内外超 2000 家金融机构（含 800+ 银行） |
| 前沿方向 | 无核架构（Coreless）、AI 原生核心、《2030 展望下一代银行核心系统蝶变之道》白皮书 |

**官方定位**（2022 年度报告原文）：

> "公司以 ModelB@nk5.0 未来银行应用架构为指引'蓝图'，基于'数云融合'的技术范式，通过独创的五层架构体系，以技术中台、数据中台以及金融超脑为支柱，通过分布式、中台化、云原生等技术应用，支撑银行的数字金融可持续发展。"

## 2. 历代版本演进

### 演进总表

| 版本 | 时间 | 架构关键词 | 核心内容 |
|------|------|-----------|---------|
| **1.0** | 2000 | 集中式架构、国产化核心 | 以国产化银行核心业务系统为支撑的集中式架构，打破国外产品垄断，大幅降低核心系统建设费用，开启国内中小银行核心建设序幕；2005 年发布国内首个国产化银行核心业务系统；集合自有 20 余款金融应用软件，发布国内首个银行整体解决方案 |
| **2.0** | 2007 | SOA、以客户为中心 | 背景：2006 年底中国金融市场全面开放、外资银行涌入。采用标准化、构件化、参数化设计理念，率先将国际水平银行业务应用系统在 SOA 体系下整合，改变国内银行科技建设无序局面，构建面向服务的 IT 架构体系 |
| **3.0** | 2010 | 产品族、前中后台 | 引入体系化"产品族"概念，对银行应用系统进行标准化划分，从前、中、后台维度清晰划分银行业务系统和 IT 架构 |
| **4.0** | 2015 | 分布式、微服务、互联网+ | 国内首款面向"互联网+"的银行 IT 应用架构解决方案。以云计算为支撑，以服务层次化、系统平台化为设计理念，助推银行架构向开放化发展，构建微服务化敏捷架构体系 |
| **5.0** | 2021 | 云原生、数云融合、五层架构 | 历经六年打磨，详见第 3 节 |
| **（前瞻）** | 2026 | 无核化（Coreless）、AI 原生 | 从"胖核心"到"瘦核心"再到"无核"，详见第 6 节 |

### 发布 5.0 的三大技术背景（郭为，2021 服贸会演讲）

1. **烟囱式系统问题**：过去银行系统独立建设，虽通过总线结构实现互连且体系稳健，但在以场景、以客户为中心的新金融消费体系下，原有结构显得笨重、不够敏捷。
2. **交易处理与数据处理割裂**：银行拥有大量数据，但数据无法实时体现在服务、客户体验和新产品设计中，现有 IT 架构存在缺失。
3. **IT 架构落后制约金融服务能力**：制约综合金融、产业金融服务能力；传统银行核心与互金核心"两个核心"并存，关联关系在旧架构中无体现；叠加信创工程（当年 120 家银行单位试点）提出的新命题。

### 郭为的"双视角"理念

不仅要从银行视角看业务（追求稳健），还要加入客户视角（提倡敏捷），通过双视角思考未来 IT 架构发展方向，解决银行业务发展遇到的弊端和瓶颈。

## 3. ModelB@nk5.0 架构详解

> 资料主体来源：神州信息官网产品页 `/product-and-solution/MB5.0` + 2022 年度报告 + 《金融电子化》发布报道

### 3.1 系统概述

ModelB@nk5.0 是**面向未来的银行 IT 架构**：

- 基于云原生和微服务体系，结合数据实时分析能力
- 利用金融超脑的 AI 能力，全面释放应用系统潜力，支撑数字金融可持续发展
- 以**场景化、旅程化、中台化**的细分功能赋能客户生产生活
- 构建银行从大零售、产业金融到投资领域的专业化金融服务体系
- 帮助金融机构创新业务模式、发挥数据价值，更好服务实体经济

### 3.2 解决的三大行业痛点

1. **单体系统为单位提供功能**：系统间打通交互能力弱；总线结构下的互联在"以场景、以客户为中心"的新消费体系下笨重、不敏捷。
2. **交易处理与数据处理相对割裂**：数据价值无法快速体现到业务上。
3. **制约综合金融服务能力**：IT 架构缺失或落后制约综合金融、产业金融服务能力，特别是典型产业场景的快速服务能力。

### 3.3 三大支柱

| 支柱 | 功能定位 |
|------|---------|
| **技术中台** | 提供统一微服务框架，充分发挥分布式技术带来的性能和部署优势，实现整体的开发运维一体化（DevOps）智能管理 |
| **数据中台** | 实现数据的实时分析、传输和利用，对数据价值进行重塑，快速将数据价值释放到业务处理及经营管理过程；提供数据治理、数据建模、数据开发、数据分析、数据服务等一系列服务与组件 |
| **金融超脑** | 提供整套 AI 能力应用（产品化为 Sm@rtFSB，见第 4 节），帮助业务系统和技术平台实现不同的智能化需求，释放更大潜能 |

### 3.4 五层架构体系

```
┌─────────────────────────────────────────────────┐
│  第五层：组织管理层（监管 / 审计 / 经营管理）        │
├─────────────────────────────────────────────────┤
│  第四层：资源积累层（湖仓一体数据资源沉淀）          │
│  （客户 / 外部 / 政府 / 机构数据资源）               │
├─────────────────────────────────────────────────┤
│  第三层：能力输出层（七大中台体系）                  │
│  ├ 业务中台：内管 | 业务处理 | 营销 | 风控          │
│  └ 基础技术：数据中台 | 技术中台 | 金融超脑          │
├─────────────────────────────────────────────────┤
│  第二层：旅程服务层【核心层次】                     │
│  （用户旅程 | 产品服务 | 资金投资）                  │
├─────────────────────────────────────────────────┤
│  第一层：场景建设层                                │
│  （线上线下融合服务 + 跨行业生态场景）               │
└─────────────────────────────────────────────────┘
```

**第一层：场景建设层**
- 定位：帮助拓展业务触角、提供统一交互体验、输出整体品牌形象
- 建成"柜台服务、移动服务、远程服务与客户自助服务"相结合的线上线下融合服务模式
- 依托生态链系统体系广泛开展跨行业合作，建立社群、农银、税银、银企、学银、供应链、交易市场等不同领域的融合场景，将金融服务扎根于用户生产生活
- 崔蕾观点：不同金融企业数字化建设最关键的就是场景建设

**第二层：旅程服务层（核心层次）**
- 组成：用户旅程、产品服务、资金投资三部分相关系统
- 理念：按用户在特定场景下的不同服务需求定制"千人千面"的流程体验及产品服务，让用户"宛如在高端旅行中一般，舒服自然地享受不同内容的金融服务过程"
- 作用：帮助银行增强客户粘性

**第三层：能力输出层**
- 金融企业将基础能力以集中方式向旅程服务输出的系统层次
- **七个中台体系** = 业务层面四大中台（内管中台、业务处理中台、营销中台、风控中台）+ 基础技术能力三大中台（数据中台、技术中台、金融超脑）

**第四层：资源积累层**
- 通过湖仓一体技术沉淀和管理业务过程中的数据资源：用户数据、外部数据、政府数据、机构数据资源等
- 沉淀的数据资源通过数据中台实现实时分析、传输和利用，快速将数据价值释放到业务处理及经营管理过程
- 目标：将业务数据化、模型化，将三农、中小微企业的数据要素转化为金融资产

**第五层：组织管理层**
- 面向金融企业监管、审计和经营管理等组织管理层面的系统层
- 保障金融企业平稳运行发展的根基
- 通过数据中台、金融超脑对数据价值的重塑，该层系统更加强调智能化，帮助金融机构由内而外实现组织管理的数字化转型

### 3.5 客户价值

1. 为金融机构 IT 架构演进提供清晰的方向性指引
2. 帮助金融机构由内而外实现组织管理的数字化转型
3. 五层系统在统一微服务框架下发挥分布式技术的性能与部署优势
4. 实现整体开发运维一体化（DevOps）智能管理
5. 帮助创新业务模式、发挥数据价值
6. 构建从大零售、产业金融到投资领域的专业化金融服务体系，服务实体经济

### 3.6 农业产业链场景实例（新华网访谈，崔蕾）

| 环节 | 架构层应用 |
|------|-----------|
| 购买种苗 | "场景建设"层打通种子公司销售平台，通过种苗存活率直接提供小额贷款 |
| 物流运输 | 打通物流平台，帮助农户选择合适物流方式并结算费用 |
| 加工销售 | 建设农产品加工社群，对接加工企业和销售卖场信息 |
| 服务优化 | "旅程服务"层优化播种季节放款速度、物流结算方式，提供针对性金融产品 |
| 金融服务 | "能力输出"层输出存、贷、汇服务，借助 AI 和实时数据智能化处理 |
| 风险防控 | "资源积累"层基于三农数据积累分析防范农业生产风险 |
| 经营升级 | "组织管理"层实现数字化经营模式升级 |

### 3.7 敏态与稳态的重新划分（《银行家》专题，崔蕾，2022-04）

ModelB@nk5.0 的重要创新：**不再按垂直业务范围（如线上/线下、零售/对公）划分稳态和敏态，而是从客户视角横向划分**——直接面向客户的场景建设和旅程服务属于**敏态**；支撑敏态业务的能力沉淀和资源积累才是**稳态**。这种划分可优化客户服务、集中标准化处理降低成本、管控风险，并通过旅程服务闭环（服务→客户反馈→优化）提升体验、增强黏性。

### 3.8 金融科技 2.0 架构体系两极（2021 年度报告）

2021 年 8 月神州信息发布"神州信创云"全家桶架构蓝图（全栈自主可控底座）。**"神州信创云"与 ModelB@nk5.0 一道，形成金融科技 2.0 架构体系的两极，在基础层和应用层分别为金融机构数字化升级提供全面的技术底座和能力支持。**

### 3.9 信创定位

官网将 ModelB@nk5.0 整体解决方案归入"金融信创 → 信创架构规划及设计"类目：通过对未来 IT 架构的整体规划设计，帮助银行建立符合自身特点及**信创要求**的技术和应用体系。

信创三层次（赵巍，神州信息金融信创首席专家）：
1. 一般应用信创（办公 OA、邮件等适配替代）
2. 云及数字底座（国产软硬件 + 虚拟化/分布式，"一次适配，多次复用"）
3. 全栈信创架构建设（完全基于国产生态的数字化平台，云原生、数字原生新一代 IT 整体信创架构）

## 4. 金融超脑 Sm@rtFSB

> 来源：《金融电子化》2021-08 报道、中国电子银行网

与 ModelB@nk5.0 同日（2021-08-12）发布，是其三大支柱中"金融超脑"的产品化落地。

**定位**：企业级金融 AI 核心系统 / 金融 AI 中台解决方案，基于人工智能前沿、大数据、云计算及区块链等底层技术。

**"一基一核两翼"技术架构**：

1. **金融 AI 开发平台（基）**
   - 基于云原生和微服务架构的 kubeflow 框架，模型构建高效便捷
   - 自动化 CI/CD 系统，支持数据科学家快速探索特征工程、模型架构和超参数
   - 资源隔离、流水线高效建模、自动部署，实现建模流程 AIOps
2. **感知能力平台（翼一）**
   - 智能语音 + 计算机视觉两个核心组件
   - 深度语义模型、金融实体库提升精准度；图像/文字双模态对齐
   - 应用：对话系统、项目经理抽检、视频银行
3. **认知能力平台（翼二）**
   - NLP、知识图谱和图模型组件
   - 全流程知识工程，实现从思考、预热、推理到决策的体系化推理决策能力
   - 应用：文本理解、AI 反洗钱、资金头寸管理

**能力体系**：智能营销、智能风控、智能运营、农业普惠金融、小微企业融资等一整套 AI 能力。

（谢国斌，神州信息人工智能首席专家：金融超脑带来"AI 前沿技术研发 + 新基建技术融合 + 金融场景商业落地"的完整闭环模型。）

## 4A. 专家观点与落地实践（成套深度资料）

> 来源：《银行家》杂志 2022 年专题（崔蕾署名）、《金融电子化》2023-01《ModelB@nk5.0 的实践启示》、郭为《数字化的力量》

### 4A.1 郭为《数字化的力量》对 ModelB@nk5.0 的定性（三点意义）

1. **前瞻性的架构体系**
2. **场景融合的服务延伸**
3. **数云融合的技术范式体系**

崔蕾论断："ModelB@nk5.0 并非神州信息设计而来，而是金融行业一旦迈上数字化转型之路，就会自然而然地沿着这一架构思路前行。它的可行性和指引性是水到渠成的事情，神州信息的幸运在于预见和创新。"

### 4A.2 崔蕾四大预判（《金融电子化》2023-01）

1. **必须把数据资产放到数据建设的核心位置**：数据资产是企业最核心的竞争能力；部分区域头部银行已将数据资产管理作为承接数据治理的重要工作，用数据资产做"汽油"、数据工具做"发动机"，将数据服务直接应用于客服、营销、风控和运营。
2. **核心业务系统逐步向中台化发展**：当产品中心、客户中心、定价中心、贷款中心、存款中心等都发展为独立且可灵活组合的中台系统，核心业务系统完全可以由多个中台构建而成。
3. **搭建场景建设平台应对未来场景快速创新**：案例——某国有大行金融生态云平台推出 SaaS 产品，结合伙伴能力建设教育、出行、景区等场景。
4. **通过模型有效管理银行的业务资产**：把人脑的经验和记忆沉淀到模型中，实现业务全流程数字化。

### 4A.3 2022 年落地实践成果（按五层架构对应）

## 6. 2026 最新演进：无核架构（Coreless）

> 来源：2026 华为全联接大会（崔蕾演讲）、2026 香港金融科技周、数云原力 2026·数智金融论坛

### 6.1 核心系统三阶段演进论（崔蕾，2026-09）

1. **Bank1.0/2.0 —"胖核心"**：集中式单体架构，整合存贷汇、计息及客户管理，账务强一致；痛点是刚性过高，"牵一发而动全身"
2. **Bank3.0/4.0 —"瘦核心"**：SOA + 分布式微服务支撑下，ECIF、总账、流程等非本质功能外迁，核心回归金融资产权属管理与记账
3. **AI 时代 —"无核心"**：AI 让金融服务极致微服务化成为可能，全面支撑智能体（AI Agent）应用，取消绝对集中的单体中心，实现完全组件化部署

### 6.2 "无核"的本质

**"无核"不是没有核心，而是以"原子积木"形式进行极致能力的拆解**：
- 各中心不再是传统软件模块，而是分布在"语义织物"上的"原子积木"
- 通过标准化智能体接口对外暴露能力，每个中心彻底服务化、能力中台化，独立部署、自成一体、全行共享
- 共同构成智能金融时代可信、敏捷、弹性的业务底座
- 设计理念从"流程驱动"迈向"意图驱动"，支持"像乐高积木一样快速进行产品创新与灵活定价"（SSOT 单一事实来源）

### 6.3 AI 能力矩阵（四层 × 能力中心）

四层 AI 能力（数据识别、智能处理、智能计算、内容生成）与客户、账户、合约、产品、定价、交易、运营、核算等能力中心交叉融合：
- 智能识别：涉赌涉诈交易风险识别、交叉违约与重复担保识别、客户信息智能合并去重
- 自动化处理：线上一键开户、定价利率自动生成、合约变更终止全流程自动化、资金清算对账自动化
- 预测计算：交易风险实时评分、"一户一价、一笔一价"风险定价、对公现金流预测与贷后预警
- 内容生成：智能客户画像、流水解读与收支分析、定价周报月报自动生成、标准化合约文本生成

### 6.4 智能体成为核心系统的"用户"

- SoE/SoI 层系统成为智能体驱动的 AI 原生应用；以核心为代表的 SoR 记录类系统转变为智能体运行的数据基础设施与 MCP Server
- 各能力中心以唯一、真实的精确数据为智能体决策提供确定性"事实锚点"，消除 AI 决策"幻觉"；记录信息快照与"意图哈希"构建不可篡改的事实证据链，确保监管可解释性

### 6.5 "本体层"与语义织物

各能力中心将成为未来银行**本体层（Ontology）的单一事实来源底座**。"语义织物"通过实时映射将分散在各能力中心的原子化"事实"以逻辑链接串联，当智能体发起"优化全行资产配置"这类宏观意图时，能瞬时跨中心构建全局一体的"逻辑镜像"，实现跨中心因果推理与最优执行路径规划。（配套发布"银行本体论"研究成果，2026 数云原力论坛）

### 6.6 Web3 与数字货币原生支撑

客户中心关联公链 DID 与可验证凭证；交易中心跨链/链上链下混合交易编排；核算中心数字资产科目与链上钱包对账；支持央行数字货币与稳定币双层运营体系下的钱包管理、代币化存款兑换及 RWA 代币化发行、托管与链上链下价值映射。
